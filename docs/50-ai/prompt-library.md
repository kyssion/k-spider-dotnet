# 任务提示模板

> 状态：已确认
> 最后更新：2026-11-09
本文范围：可直接复制的任务提示模板。流程与门禁见 [change-protocol.md](change-protocol.md) 与
[definition-of-done.md](definition-of-done.md)。

## 使用方式

模板只提供任务结构，不替代阅读文档。复制后在尖括号处填入具体范围；不确定的契约先提问，不要让代理自行假设。


## 新增 crawler 数据源

```text

范围：adapter / parser / channel 配置；不改调度主流程，不新增业务表。
先读 docs/10-architecture/crawler.md、docs/10-architecture/data-model.md 与 docs/00-overview/features.md。

- 源差异只落在 adapter + parser；HTTP 一律经 HttpGateway，不自建 HttpClient；

- 明确 write_mode、record_key 预映射、详情目标与失败重试边界；
- 用真实响应做离线夹具回归，Live 用例排除；
- 同步 crawler.md 的配置 / 待确认与 channel.extra 键表；
- 运行 ./scripts/verify.sh，并列出未覆盖项。
```

## 代码审查

```text

请按以下顺序检查：
1. 是否违反 AGENTS.md 红线；
2. 是否删除/弱化测试，是否有回归测试；
3. 契约/DDL/调度/认证变更是否先确认并同步权威文档；
4. 文档是否一处编写、其余引用，目录索引是否更新；
5. 验证命令与输出是否真实、完整。

```

## 反模式（不要这样提问）

| 反模式 | 为什么不行 |
| --- | --- |
| 「按上次说的改」 | 上下文不在仓库里，代理无法可靠复现，也无法审计 |
| 「都改一下 / 顺手优化」 | 范围不可验证，容易混入无关改动，违反小步可回滚 |
| 「跳过测试先提交」 | 违反红线；门禁失败等于没有门禁 |
| 「先改前端，后端后面再说」 | 契约顺序错乱，前后端会短暂失配 |
| 「假设某某已经可用」 | 把待确认项当成事实，后续会以错误前提实现 |
| 「只给结论，不用给输出」 | 无法区分「实际通过」与「看起来没问题」 |
