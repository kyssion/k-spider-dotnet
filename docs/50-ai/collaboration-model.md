# 协作模型

> 状态：已确认
> 最后更新：2026-11-08
> 权威范围：角色分工、阶段门禁、上下文管理、交接格式、升级（Stop and Ask）时机。变更步骤见 [change-protocol.md](change-protocol.md)。

## 角色与职责

| 角色 | 职责 | 不做什么 |
|---|---|---|
| 项目所有者 | 确认契约、不可逆决策、范围与最终交付；决定是否提交/推送 | 不替代理做未确认的实现细节 |
| AI 代理 | 定向、提案、实现、自测、同步文档、按格式汇报 | 不自行拍板契约，不擅自提交/推送，不隐瞒未验证项 |
| 评审者（可选） | 按 [definition-of-done.md](definition-of-done.md) 复核范围、测试与文档 | 不以“看起来没问题”替代实际命令 |

## 阶段门禁

1. **定向门禁**：已读 [AGENTS.md](../../AGENTS.md) 与 [docs/README.md](../README.md)，已定位相关权威文档；未读完不写代码。
2. **产物门禁**：功能有规格，结构/契约有 ADR 或待确认登记；缺产物先补，不先写实现。
3. **确认门禁**：涉及公共接口、数据模型、DDL、调度、认证、外部依赖或不可逆操作时，先获得项目所有者确认。
4. **交付门禁**：按 [definition-of-done.md](definition-of-done.md) 自检，`./scripts/verify.sh` 全绿，文档已同步，后台进程已收尾。
5. **提交门禁**：只有项目所有者明确指示时才提交或推送；不得改写远端历史。

## 上下文管理

- 每次任务开始按“AGENTS → docs/README → 相关架构文档”定向；
- 只加载 1~2 个与任务直接相关的技能，不预读全部技能；
- 长任务分段汇报，避免把未确认的假设积累到最后；
- 发现文档冲突时，以权威文档和最新 ADR 为准；仍冲突则停止提问，不自行选边。

## 交接格式

面向项目所有者的交付说明固定四段：

1. **结论**：完成 / 部分完成 / 阻塞；
2. **改动**：文件清单与每项“为什么”；
3. **验证**：实际命令与原始输出，不得只写“已通过”；
4. **差异与后续**：与规格/契约的差异、未覆盖项、建议下一步。

部分完成或阻塞时，明确列出阻塞点与需要所有者确认的事项。

## 升级（Stop and Ask）

出现以下任一情况，停止实现并提问：

- 契约、DDL、调度、认证或公共接口需要变更，但尚未登记/确认；
- 两份权威文档冲突，且没有更新的 ADR 可裁决；
- 需要引入新依赖、外部服务或真实凭据；
- 需求范围与规格不一致，或需要删除/弱化测试；
- 验证无法通过且根因不在本次改动范围内；
- 需要提交、推送、改写远端历史或执行不可逆数据操作，但没有明确指示。
