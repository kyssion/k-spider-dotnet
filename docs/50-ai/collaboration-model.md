# 协作模型

> 状态：已确认
> 最后更新：2026-11-09
本文范围：核心原则、角色分工、阶段门禁、上下文管理、交接格式、升级（Stop and Ask）时机与协作度量。
变更步骤见 [change-protocol.md](change-protocol.md)。

## 核心原则

| 原则 | 含义 | 反例 |
| --- | --- | --- |
| 上下文自包含 | 任务所需的信息都在仓库里（文档 + 代码），不依赖对话历史 | 「按上次说的改」 |
| 约定显式化 | 约定写成可检查的条款或机器守卫，而不是口头默契 | 「你懂的」 |
| 小步可回滚 | 一次改动只做一件事，能独立回滚 | 重构与功能混在一次提交 |
| 不做静默降级 | 无法完成时明确说明差距，不用 TODO 或跳过测试蒙混 | 注释掉失败用例 |

红线不在本文复述，唯一权威清单见 [AGENTS.md](../../AGENTS.md)「红线」；复述会漂移。

## 角色与职责

| 角色 | 职责 | 不做什么 |
|---|---|---|
| 项目所有者 | 确认契约、不可逆决策、范围与最终交付；决定是否提交/推送 | 不替代理做未确认的实现细节 |
| AI 代理 | 定向、提案、实现、自测、同步文档、按格式汇报 | 不自行拍板契约，不擅自提交/推送，不隐瞒未验证项 |
| 评审者（可选） | 按 [definition-of-done.md](definition-of-done.md) 复核范围、测试与文档 | 不以“看起来没问题”替代实际命令 |

### 活动分工矩阵

| 活动 | 项目所有者 | AI 代理 |
|---|---|---|
| 确定目标与优先级 | 决策 | 提供选项与代价 |
| 确认契约 / ADR | 定稿 | 起草、列备选项 |
| 写规格与验收标准 | 确认 | 起草 |
| 实现与补测试 | 评审 | 执行并给出原始输出 |
| 同步文档 | 抽查 | 同一次改动完成 |
| 判断是否完成 | 依据 DoD 判定 | 自检并列未覆盖项 |
| 提交 / 推送 | 明确指示 | 执行或等待指示 |

## 阶段门禁

| 门禁 | 进入下一阶段的条件 |
|---|---|
| 定向 | 已读 [AGENTS.md](../../AGENTS.md) 与 [docs/README.md](../README.md)，已定位相关权威文档；未读完不写代码 |
| 产物 | 功能有规格，结构/契约有 ADR 或待确认登记；缺产物先补 |
| 确认 | 公共接口、数据模型、DDL、调度、认证、外部依赖或不可逆操作已获所有者确认 |
| 交付 | [definition-of-done.md](definition-of-done.md) 自检通过；验证与进程判据符合红线 7、9、12 |
| 提交 | 红线 8：只在明确指示时提交或推送 |

## 上下文管理

- 每次任务开始按“AGENTS → docs/README → 1~2 篇相关架构文档”定向；
- 不一次性读完整 `docs/`，也不预读全部技能；技能只按任务相关性加载 1~2 个；
- 跨层改动分阶段交付：先契约/数据访问，再服务/接口/前端，每阶段都能独立验证；
- 长任务分段汇报，避免把未确认的假设积累到最后；
- 发现文档冲突时，以权威文档和最新 ADR 为准；仍冲突则停止提问，不自行选边。

## 交接格式

### 人 → AI

任务描述至少包含四项，缺一项就先追问：

```text
目标：<一句话说明要达成什么>
范围：<涉及哪个模块 / 页面 / 端点；明确不动什么>
验收：<怎样算完成，最好是可执行的断言>
约束：<性能、兼容性、时间等限制；没有写“无”>
```

### AI → 人

交付说明固定四段，验证部分必须是实际命令与原始输出：

```text
## 结论
完成 / 部分完成 / 阻塞

## 改动
文件清单与每个文件“为什么”改

## 验证
实际命令与原始输出

## 差异与后续
与规格/契约的差异、未覆盖项、建议下一步
```

部分完成或阻塞时，明确列出阻塞点与需要所有者确认的事项。

## 升级（Stop and Ask）

出现以下任一情况，停止实现并提问：

- 契约、DDL、调度、认证或公共接口需要变更，但尚未登记/确认；
- 两份权威文档冲突，且没有更新的 ADR 可裁决；
- 需要引入新依赖、外部服务或真实凭据；
- 需求范围与规格不一致，或需要删除/弱化测试；
- 验证无法通过且根因不在本次改动范围内；
- 需要提交、推送、改写远端历史或执行不可逆数据操作，但没有明确指示。

提问时附上已确认的事实、候选方案与各自代价，让所有者只需做选择题；不要用“临时方案 + TODO”蒙混。

## 协作度量

以下指标用于复盘协作是否在变好，不作为门禁或绩效指标：

| 指标 | 期望方向 |
| --- | --- |
| 因约定不一致导致的返工次数 | 下降 |
| 规格写完到实现通过的往返轮数 | 下降，目标 ≤2 |
| `./scripts/verify.sh` 首次通过率 | 上升 |
| 交付说明中明确列出未覆盖项的比例 | 100% |
