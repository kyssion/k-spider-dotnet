# 项目定位与目标

> 状态：已确认
> 最后更新：2026-11-08

k-spider 是「抓取 → 处理 → 展示」的数据平台：crawler 把外部数据站的原始载荷原样抓回 PostgreSQL，
process 消费原始载荷并产出结构化数据，web 通过 admin 的同源 API 展示与操作。

## 定位

- 一条数据链路：原始载荷原样入库，提取加工与展示分离；
- admin 是旁路控制面：负责中央调度、集群维护、认证与前端托管，不在数据链路上；
- 模块之间只依赖契约：跨服务数据交换走 PostgreSQL 或明确的协议。

## 目标

1. **机制先行，领域克制**：机制按已知变化点抽象；源差异知识只落在 adapter / parser。
2. **契约即边界**：模块间只依赖契约，不依赖实现细节。
3. **数据与执行状态分离**：业务行存数据语义，执行进度走 `exec_status`，重试细节进 `extra`。
4. **一切皆注册**：源、数据集、管线、Job、分析维度、派生表、告警规则都可注册，无手写分支。
5. **放开度量，管住成本**：不设硬编码小窗口/只读限制，用预算、血缘、配额管成本。
6. **可读性优先**：抽象不为炫技，优先惯用法和成熟模式。

## 非目标

- 不追求 v1 代码、部署单元或旧库结构的兼容；v1 归档只作历史参考。
- 不在采集侧做深解析；解析产物归 process / 分析侧。
- 不预建语义层、查询引擎或物化层；按真实需求立项。
- 不把任何单一 AI agent 的平台特定配置作为仓库约束；技能与协作约定走可移植格式。

## 成功标准

- 新增数据源只需新增 adapter / parser 并注册，不修改调度与存储主流程。
- admin 重启后能通过节点重连与对账恢复调度现场，不依赖本地持久状态。
- 原始载荷可在保留期内追溯，结构化数据可由原始载荷重放生成。
- 契约变更能按文档顺序落地，并在同一次改动中同步 DDL、文档与测试。
- 任意一次交付都能用实际命令与输出证明验证结果，而不是「看起来没问题」。
