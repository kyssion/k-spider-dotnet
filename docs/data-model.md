# 数据模型设计（物理表）

> 平台唯一的物理表设计，受 [AGENTS.md](../AGENTS.md) 数据模型六条契约约束（逐条对照见第四节）；本文 DDL 是 `db/` migration 基线的蓝本。

## 一、核心抽象：分类 → 渠道 → 列表 → 详情

所有数据源统一抽象为五张业务表：

1. **dict（枚举字典表）**——平台所有枚举的唯一真相源（列表/详情适配器、各表状态、解析器，六类）：id 显式钉死、与代码枚举数值一一对应，业务表只存数字；展示名与排序经 join 取，取值映射同步在列 COMMENT；
2. **channel_category（渠道分类表）**——树形归属：站点 → 模块 → 栏目，承载"一个 xxx 网站下的 xxx 模块的 xxx 栏目"的人读层级；主键与全部外键引用数字化，人读路径只是分类表自身的可读唯一标识；
3. **channel（数据渠道表）**——配置"有哪些数据供给单元"，挂在分类节点下（通常挂叶子），等价于 v1 一条管线的粒度；记录 **source 列表获取**的配置：`source_adapter`（列表获取适配器实现类）+ `source_parser`（列表解析器）；
4. **data_source（数据源列表表）**——资源登记：每个要抓的资源连接一行，链接不变则行不变；标题、业务时间、渠道差异化字段都是对原始载荷（`raw`，bytea）的解析投影，详情获取地址同样由适配器对 raw 现场解析（不占列）；**同时记录两组**——自己的（实际产出本行的列表获取 adapter + parser 快照）与 detail 的（详情获取 adapter + parser 计划）；
5. **data_detail（数据详情表）**——资源内容：从资源抓取产出的原始数据，只存未解析原始载荷（`raw`，bytea 任意格式），解析产物归分析侧；记录**自己的** adapter + parser（实际执行的详情获取快照，重放依据）。

行存在即详情已抓取（status 记数据事实）。「列表即全文」的源（快讯类）两表都写，详情段由列表适配器直接产出（detail_adapter 与自身同源），详情去哪查对所有渠道是同一个答案。

**adapter / parser 命名规则**：无前缀 = 本表自己的（实际作用于本行的快照）；带下游前缀（如 `detail_adapter`）= 下游阶段的配置或计划。

**source : detail = 1 : N**：source 按资源唯一性登记（一个链接一行，链接不变行不变）；detail 按内容唯一性产出——唯一键由适配器按业务要求生成、可含时间窗（榜单按天、快讯按条），同一资源可产出多份内容；文章类 1:1 是 N=1 的特例。

## 二、"获取方法"的五个层次

"怎么获取数据"在五个层次上出现，各归其位：

| 语义层次 | 问题 | 落地位置 |
|---|---|---|
| 列表**发现策略** | 怎么翻页/游标/对账 | 适配器实现（代码固化） |
| **请求**怎么发 | method / 头 / 签名 / 编码 / 限流 / 反爬放行集 | 适配器实现（代码固化） |
| **代码归属** | 列表怎么拉 / 详情怎么抓 | 配置在 channel（source_adapter + source_parser）；计划随行在 data_source（detail_adapter + detail_parser）；实际使用随行留痕（data_source、data_detail 自身 adapter + parser）——均指向代码实现类 |
| **渠道实例差异** | 栏目号 / 拉取窗口 / 批量上限 / 凭据引用名 | `channel.extra` |
| **行级获取** | 这一条数据的详情怎么拿 | 抓取目标由适配器对 source.raw 现场解析（不占列）；实际抓取地址的快照在 `data_detail.fetch_url`（溯源/重放） |

原则：适配器固化一切通用获取知识——策略、URL 模板、请求与签名、反爬放行集、载荷形式（与架构 4.2 `ISourceAdapter` 自带 FetchStrategy 的设计一致）；channel 只留"哪个适配器 + 实例参数"；行级快照随数据走。

## 三、表结构（DDL）

**通用规范（每张表必须满足）**：代理主键 `id`（bigint identity；唯一例外 dict——人工钉死 id 的枚举注册表用 int）、`create_time`（创建时间）、`update_time`（修改时间）三件套；表与列必须写 `COMMENT ON` 注释（中文、业务含义）。`id` + `update_time` 是分发引擎双键水位（新行按 Id 水位、已有行按 update_time 水位）的前提；`create_time` 即契约第 4 条 ingest_time（入库时间）的落地列名——行创建即首次入库，event_time 与之分离的契约语义不变。COMMENT 写"是什么"（业务含义，数据库工具直接可见），DDL 行内注释写"为什么"（设计理由），两者互补不重复。枚举列统一走 dict 数字外键：列名不带 `_id` 后缀、数据库只存数字、取值映射写入列 COMMENT 并与代码枚举数值对齐，新增取值三同步（migration + 代码枚举 + 列 COMMENT），规则见 5.8，不用 PG 原生 ENUM。extra 是表级扩展容器——固定列不够用时启用；新增 extra 约定键（平台代码读写新键）须先与项目所有者确认。

```sql
-- ============================================================
-- 表 0：dict 枚举字典表（平台所有枚举的唯一真相源）
-- 类型与取值随 migration 演进；编码与代码注册表对齐，
-- 业务表只存数字，展示名与排序经 join 取
-- ============================================================
CREATE TABLE dict (
    id          int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
        -- 显式钉 id（与代码枚举数值对齐），种子 migration 指定，日常插入仍可自增；
        --   int：行数人工封顶的注册表，且与 C# 枚举默认底层类型（int）一致
    type        text NOT NULL
        CHECK (type IN ('list_adapter', 'detail_adapter', 'channel_status', 'enable_status',
                        'item_status', 'parser')),
        -- 字典类型（发版演进）：新增类型/取值时随 migration 加值
    code        text NOT NULL,                -- 稳定编码，与代码注册表对齐
    name        text NOT NULL,                -- 展示名
    sort_no     int NOT NULL DEFAULT 0,
    status      text NOT NULL DEFAULT 'active'
        CHECK (status IN ('active', 'disabled')),
        -- 自举例外（见 5.8）：dict 是枚举机制自身的载体，启停标记不再引用自身
    remark      text,
    create_time timestamptz NOT NULL DEFAULT now(),
    update_time timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT dict_uk UNIQUE (type, code)    -- 同类型内编码唯一
);
COMMENT ON TABLE dict IS '枚举字典表：平台所有枚举的唯一真相源（六个字典类型）';
COMMENT ON COLUMN dict.id IS '代理主键：显式种子，数值与代码枚举一一对应（int，人工封顶）';
COMMENT ON COLUMN dict.type IS '字典类型：list_adapter/detail_adapter/channel_status/enable_status/item_status/parser（发版演进）';
COMMENT ON COLUMN dict.code IS '稳定编码，与代码注册表对齐';
COMMENT ON COLUMN dict.name IS '展示名';
COMMENT ON COLUMN dict.sort_no IS '同类型内排序';
COMMENT ON COLUMN dict.status IS '启停：active/disabled（自举例外，不引用自身）';
COMMENT ON COLUMN dict.remark IS '备注';
COMMENT ON COLUMN dict.create_time IS '创建时间';
COMMENT ON COLUMN dict.update_time IS '修改时间';

-- 初始化基线：id 显式钉死（代码枚举按此数值实现），已分配 id 永不复用，新增取值顺延并三同步
INSERT INTO dict (id, type, code, name) VALUES
    (1,  'enable_status',  'active',   '启用'),
    (2,  'enable_status',  'disabled', '停用'),
    (3,  'channel_status', 'active',   '启用中'),
    (4,  'channel_status', 'paused',   '已暂停'),
    (5,  'channel_status', 'retired',  '已退役'),
    (6,  'item_status',    'normal',    '正常'),
    (7,  'item_status',    'filtered',  '已过滤'),
    (8,  'item_status',    'dead',      '源站已删'),
    (9,  'item_status',    'paywalled', '付费墙'),
    (10, 'list_adapter',   'cls',       '财联社列表适配器'),
    (11, 'list_adapter',   'eastmoney', '东方财富列表适配器'),
    (12, 'detail_adapter', 'cls',       '财联社详情适配器'),
    (13, 'detail_adapter', 'eastmoney', '东方财富详情适配器');
    -- parser（解析器）不预置：行随适配器开发逐个登记
SELECT setval(pg_get_serial_sequence('dict', 'id'), (SELECT max(id) FROM dict));

-- ============================================================
-- 表 1：channel_category 渠道分类表（树形归属：站点 → 模块 → 栏目）
-- 承载"xxx 网站的 xxx 模块的 xxx 栏目"的人读层级；引用键全部数字化，
-- path 物化路径只作分类表自身的可读唯一标识
-- ============================================================
CREATE TABLE channel_category (
    id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    parent_id   bigint REFERENCES channel_category(id),   -- NULL = 根（站点级）；层级深度由链表达
    name        text NOT NULL,                            -- 分类名：财联社 / 电报快讯 / 要闻
    path        text NOT NULL UNIQUE,                     -- 物化路径 'cls/flash'：人读 + 子树查询
    sort_no     int NOT NULL DEFAULT 0,                   -- 同层排序（控制台展示）
    status      int NOT NULL REFERENCES dict(id),         -- 启停（dict type=enable_status，映射见列 COMMENT）
    create_time timestamptz NOT NULL DEFAULT now(),
    update_time timestamptz NOT NULL DEFAULT now()
);
COMMENT ON TABLE channel_category IS '渠道分类表：树形归属（站点→模块→栏目），人读层级的唯一归属地';
COMMENT ON COLUMN channel_category.id IS '代理主键';
COMMENT ON COLUMN channel_category.parent_id IS '父分类，NULL=根（站点级）';
COMMENT ON COLUMN channel_category.name IS '分类名';
COMMENT ON COLUMN channel_category.path IS '物化路径（如 cls/flash）：人读 + 子树查询，同层不重复';
COMMENT ON COLUMN channel_category.sort_no IS '同层排序';
COMMENT ON COLUMN channel_category.status IS '启停（dict type=enable_status）：1=active 启用/2=disabled 停用；新增取值须同步本注释';
COMMENT ON COLUMN channel_category.create_time IS '创建时间';
COMMENT ON COLUMN channel_category.update_time IS '修改时间';
-- 删除保护：有 channel 挂载或有子节点的分类禁止删除（应用层保证，不建约束）

-- ============================================================
-- 表 2：channel 数据渠道（配置表，平台能力的挂载点）
-- 挂在分类节点下（通常叶子），粒度等价一条采集管线；
-- 吸收架构文档里 source + dataset 两层，channel 即"源下逻辑数据实体"
-- ============================================================
CREATE TABLE channel (
    id             bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    -- ── 身份 ──
    category_id    bigint NOT NULL REFERENCES channel_category(id),
                                           -- 归属分类（树形：站点→模块→栏目，通常挂叶子）；
                                           --   内容域由站点级归属与适配器推导，不设独立列
    channel_name   text NOT NULL,
    description    text,                  -- 人读说明：站点侦察结论 / 已知坑的就近落点
    -- ── 接入 ──
    source_adapter int NOT NULL REFERENCES dict(id),
                                           -- source 列表获取适配器（dict type=list_adapter，映射见列
                                           --   COMMENT）：source（数据源列表）获取的实际操作逻辑实现类
                                           --   （配置级）；抓取方式（策略/URL模板/请求签名/反爬放行集）
                                           --   与载荷形式全部固化在适配器实现里（见第二节）
    source_parser  int NOT NULL REFERENCES dict(id),
                                           -- source 列表解析方法（dict type=parser）：解析器实现类引用，
                                           --   行随适配器开发登记
    -- ── 治理 ──
    retention_days int CHECK (retention_days IS NULL OR retention_days > 0),
                                           -- 保留期声明，NULL = 永久（契约第 5 条）
    -- ── 调度与监控 ──
    schedule       jsonb NOT NULL DEFAULT '{}',   -- 拉取节奏：间隔/cron + 并发互斥声明
    monitor        jsonb NOT NULL DEFAULT '{}',
        -- 监控阈值声明：新鲜度告警（快讯类分钟级 / 政策类天级）、可用性判定窗口；
        --   健康探测"注册即覆盖"的依据
    last_success_at timestamptz,
        -- 最近一次成功拉取：监控任务回写的运维缓存，可从 max(data_source.create_time) 重算；
        --   冗余存是为控制台渠道全景一次查询免逐渠道聚合
    -- ── 状态与兜底 ──
    status         int NOT NULL REFERENCES dict(id),
        -- 渠道状态（dict type=channel_status，映射见列 COMMENT）；写入由代码枚举显式赋值
    extra          jsonb NOT NULL DEFAULT '{}',
        -- 渠道级实例参数（适配器的差异化输入）：栏目号/频道参数、拉取窗口、停机回补上限、
        -- 每轮批量上限、凭据引用名（credential_key 键，只存引用不存值，真实凭据环境注入）等
    create_time    timestamptz NOT NULL DEFAULT now(),
    update_time    timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT channel_uk UNIQUE (category_id, channel_name)   -- 同分类下渠道名唯一
);
COMMENT ON TABLE channel IS '数据渠道表：一个可拉取的数据供给单元（挂在分类节点下），平台能力的挂载点';
COMMENT ON COLUMN channel.id IS '代理主键';
COMMENT ON COLUMN channel.category_id IS '归属分类（channel_category.id），通常挂叶子';
COMMENT ON COLUMN channel.channel_name IS '渠道名（同分类下唯一）';
COMMENT ON COLUMN channel.description IS '人读说明：站点侦察结论/已知坑';
COMMENT ON COLUMN channel.source_adapter IS 'source 列表获取适配器（dict type=list_adapter）：下游数据源列表获取的实现类';
COMMENT ON COLUMN channel.source_parser IS 'source 列表解析方法（dict type=parser）：下游列表的解析器实现类';
COMMENT ON COLUMN channel.retention_days IS '保留期（天），NULL=永久';
COMMENT ON COLUMN channel.schedule IS '拉取节奏：间隔/cron + 并发互斥声明';
COMMENT ON COLUMN channel.monitor IS '监控阈值：新鲜度告警/可用性判定窗口';
COMMENT ON COLUMN channel.last_success_at IS '最近一次成功拉取（监控回写缓存，可从数据重算）';
COMMENT ON COLUMN channel.status IS '渠道状态（dict type=channel_status）：3=active 启用中/4=paused 已暂停/5=retired 已退役；新增取值须同步本注释';
COMMENT ON COLUMN channel.extra IS '渠道级实例参数：栏目号/窗口/批量上限/凭据引用名等';
COMMENT ON COLUMN channel.create_time IS '创建时间';
COMMENT ON COLUMN channel.update_time IS '修改时间';

-- ============================================================
-- 表 3：data_source 数据源列表（资源登记：每个要抓的资源连接一行）
-- ============================================================
CREATE TABLE data_source (
    id            bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    channel_id    bigint NOT NULL REFERENCES channel(id),   -- 渠道数字外键
    record_key    text NOT NULL,          -- 资源唯一键，格式「渠道前缀id:sha256」；
                                          --   预映射 = 适配器按资源唯一性要求从载荷解析的唯一标识
                                          --   （文章id/doc_id/url 唯一段等），同一链接同一行；
                                          --   哈希由应用层计算、PG 只存储不参与计算（代码逻辑）；
                                          --   生成规则适配器声明、选定后不可换（去重键稳定性，契约第 2 条）
    title         text,                   -- 解析投影：标题（最热字段实物列，其余差异化字段进 extra）
    event_time    timestamptz,            -- 解析投影：业务时间（源站发布时间），列表不带时可为空、
                                          --   详情段回填修正（与 create_time 分离，契约第 4 条）
    adapter       int NOT NULL REFERENCES dict(id),
        -- 列表获取适配器快照（dict type=list_adapter，映射见列 COMMENT）：
        --   实际产出本行的渠道列表获取实现类（溯源：谁拉到了这条数据）
    parser        int NOT NULL REFERENCES dict(id),
        -- 列表解析器快照（dict type=parser）：实际解析出本行的解析器实现类
    raw           bytea NOT NULL,         -- 原始载荷：列表响应中本条目的未解析原文（JSON 片段/HTML 分段）；
                                          --   title/event_time/extra 均由 parser 对本列解析产出，
                                          --   详情获取地址同样现场解析（不占列）；
                                          --   解析重放基于本列；格式不限（同 data_detail.raw）
    detail_adapter int NOT NULL REFERENCES dict(id),
        -- 详情获取适配器（dict type=detail_adapter）：本条数据的详情怎么抓的实现类；
        --   「列表即全文」场景与自身同源，由列表适配器直接产出详情，无二次获取
    detail_parser int NOT NULL REFERENCES dict(id),
        -- 详情解析方法（dict type=parser）：本条详情的解析器实现类引用
    status        int NOT NULL REFERENCES dict(id),
        -- 数据事实状态（dict type=item_status，映射见列 COMMENT）；
        --   "详情抓没抓到"是推导态（表 4 有无此行），失败计数等执行态在 extra 扩展字段
    extra         jsonb NOT NULL DEFAULT '{}',
        -- 渠道差异化字段：summary / author / 栏目 / 机构 / 文号 / 是否付费 / 榜单数值 ...；
        --   执行态约定键（fail_count/next_retry_at/last_error，已确认）也在此，可重建清理；
        --   新增约定键须先与项目所有者确认
    content_hash  text,                   -- 载荷哈希（raw 的哈希）：资源元数据/载荷被源站修订时才有变化
    create_time   timestamptz NOT NULL DEFAULT now(),
    update_time   timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT data_source_uk UNIQUE (channel_id, record_key)   -- 契约第 2 条：去重键
);
COMMENT ON TABLE data_source IS '数据源列表表：资源登记（每个要抓的资源连接一行，元数据为载荷解析投影）';
COMMENT ON COLUMN data_source.id IS '代理主键';
COMMENT ON COLUMN data_source.channel_id IS '归属渠道（channel.id）';
COMMENT ON COLUMN data_source.record_key IS '资源唯一键：适配器按资源唯一性要求从载荷解析的唯一标识（文章id/doc_id/url唯一段等）；哈希应用层计算、PG只存储；选定不可换';
COMMENT ON COLUMN data_source.title IS '解析投影：标题（最热字段实物列）';
COMMENT ON COLUMN data_source.event_time IS '解析投影：业务时间（源站发布时间），与 create_time 分离';
COMMENT ON COLUMN data_source.adapter IS '列表获取适配器快照（dict type=list_adapter）：实际产出本行的实现类';
COMMENT ON COLUMN data_source.parser IS '列表解析器快照（dict type=parser）：实际解析出本行的实现类';
COMMENT ON COLUMN data_source.raw IS '原始载荷：列表响应中本条目的未解析原文，各投影列由 parser 对本列解析产出；重放依据';
COMMENT ON COLUMN data_source.detail_adapter IS '详情获取适配器（dict type=detail_adapter）：本条数据详情获取的实现类；列表即全文场景与自身同源';
COMMENT ON COLUMN data_source.detail_parser IS '详情解析方法（dict type=parser）：本条详情的解析器实现类';
COMMENT ON COLUMN data_source.status IS '数据事实状态（dict type=item_status）：6=normal 正常/7=filtered 已过滤/8=dead 源站已删/9=paywalled 付费墙；新增取值须同步本注释';
COMMENT ON COLUMN data_source.extra IS '渠道差异化扩展字段 + 执行态约定键（新增约定键须先与项目所有者确认）';
COMMENT ON COLUMN data_source.content_hash IS '载荷哈希（raw 的哈希）：覆盖式写入的跳过更新依据';
COMMENT ON COLUMN data_source.create_time IS '创建时间（首次入库）';
COMMENT ON COLUMN data_source.update_time IS '修改时间（同步水位键之一）';

CREATE INDEX data_source_time_idx  ON data_source (event_time DESC);   -- 新鲜度/归档剪枝
CREATE INDEX data_source_sync_idx ON data_source (update_time, id);   -- 分发双水位

-- ============================================================
-- 表 4：data_detail 数据详情（资源抓取产出的原始内容，source : detail = 1 : N）
-- 只记录未解析原始载荷（raw），解析产物归分析侧；行存在 = 详情已抓取
-- ============================================================
CREATE TABLE data_detail (
    id            bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    channel_id    bigint NOT NULL,        -- 冗余渠道（与 source 一致，便于按渠道查询/归档）
    source_id     bigint NOT NULL REFERENCES data_source(id),
                                          -- 来源资源（一个资源可产出多份内容）
    record_key    text NOT NULL,          -- 内容唯一键，格式「渠道前缀id:sha256」；
                                          --   预映射 = 适配器按内容唯一性要求生成、可含时间窗
                                          --   （榜单按天、快讯按条），同一资源可产出多份内容；
                                          --   哈希由应用层计算、PG 只存储不参与计算（代码逻辑）；
                                          --   生成规则适配器声明、选定后不可换（去重键稳定性，契约第 2 条）
    fetch_url     text NOT NULL,          -- 抓取态快照：实际请求的地址（可能经重定向）
    adapter       int NOT NULL REFERENCES dict(id),
        -- 详情获取适配器快照（dict type=detail_adapter）：实际抓取本详情的实现类（重放依据）
    parser        int NOT NULL REFERENCES dict(id),
        -- 详情解析器快照（dict type=parser）：实际解析出本详情的实现类
    raw           bytea NOT NULL,         -- 原始数据：未解析的原始载荷，格式不限（文本/二进制/图片/
                                          --   复合或自定义结构），格式定义与解码在 adapter、PG 只存字节；
                                          --   解析重放基于本列，解析产物归分析侧
    content_hash  text,                   -- 载荷哈希（raw 的哈希）：同键重抓哈希变才覆盖
    status        int NOT NULL REFERENCES dict(id),
        -- 数据事实状态（dict type=item_status，映射见列 COMMENT）：
        --   normal 正常 / filtered 已过滤 / dead 源站已删 / paywalled 付费墙
    extra         jsonb NOT NULL DEFAULT '{}',
        -- 扩展字段：附件链接等差异化信息 + 执行态约定键（fail_count/next_retry_at/last_error，
        --   已确认）；新增约定键须先与项目所有者确认
    event_time    timestamptz,            -- 详情页修订后的准确业务时间（源站事实）
    create_time   timestamptz NOT NULL DEFAULT now(),
    update_time   timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT data_detail_uk UNIQUE (source_id, record_key),   -- 同一资源下内容键唯一
    CONSTRAINT data_detail_fk FOREIGN KEY (source_id)
        REFERENCES data_source (id) ON DELETE CASCADE
);
COMMENT ON TABLE data_detail IS '数据详情表：资源抓取产出的原始内容（source:detail=1:N，未解析原始载荷，行存在=详情已抓取）';
COMMENT ON COLUMN data_detail.id IS '代理主键';
COMMENT ON COLUMN data_detail.channel_id IS '归属渠道（冗余，与 source 一致）';
COMMENT ON COLUMN data_detail.source_id IS '来源资源（data_source.id），同一资源可产出多份内容';
COMMENT ON COLUMN data_detail.record_key IS '内容唯一键：适配器按内容唯一性要求生成、可含时间窗；哈希应用层计算、PG只存储；选定不可换';
COMMENT ON COLUMN data_detail.fetch_url IS '详情抓取地址（抓取态快照，溯源/重放）';
COMMENT ON COLUMN data_detail.adapter IS '详情获取适配器快照（dict type=detail_adapter）：实际抓取本详情的实现类';
COMMENT ON COLUMN data_detail.parser IS '详情解析器快照（dict type=parser）：实际解析出本详情的实现类';
COMMENT ON COLUMN data_detail.raw IS '原始数据：未解析原始载荷（bytea 任意格式：文本/二进制/图片/自定义结构），解码在 adapter；重放依据';
COMMENT ON COLUMN data_detail.content_hash IS '载荷哈希（raw 的哈希）：同键重抓哈希变才覆盖';
COMMENT ON COLUMN data_detail.status IS '数据事实状态（dict type=item_status）：6=normal/7=filtered/8=dead/9=paywalled；新增取值须同步本注释';
COMMENT ON COLUMN data_detail.extra IS '扩展字段：附件链接等差异化信息 + 执行态约定键（新增约定键须先与项目所有者确认）';
COMMENT ON COLUMN data_detail.event_time IS '详情页修订后的准确业务时间';
COMMENT ON COLUMN data_detail.create_time IS '创建时间（首次入库）';
COMMENT ON COLUMN data_detail.update_time IS '修改时间（同步水位键之一）';

CREATE INDEX data_detail_time_idx  ON data_detail (event_time DESC);
CREATE INDEX data_detail_sync_idx ON data_detail (update_time, id);
```

## 四、与数据模型六契约的对照

| # | 契约 | 落地 |
|---|---|---|
| 1 | 业务行只存数据语义；执行态记录在行内扩展字段 | data_source/data_detail 无游标、阶段状态列；失败计数/重试时间等执行态在 extra 扩展字段（约定键，可重建清理）；渠道配置在 channel |
| 2 | 去重键稳定 `(dataset_id, record_key)` | source：`(channel_id, record_key)`（资源唯一性）；detail：`(source_id, record_key)`（内容唯一性，1:N）；record_key 恒为「渠道前缀id:sha256」，预映射由适配器声明 |
| 3 | 写入语义唯一：覆盖式 upsert | 适配器声明（渠道不配置），落法见 5.4；历史快照由 detail 内容键含时间窗表达 |
| 4 | `event_time` 与 `ingest_time` 分离 | data_source/data_detail 均为双时间列，ingest_time 落地列名 `create_time`（见通用规范）；data_detail.event_time 是详情修订后的准确值，分析层以 data_detail 为准（`coalesce(c.event_time, i.event_time)`） |
| 5 | 按 event_time 分区（或等价分批归档）+ 保留期 | `retention_days` 声明；首期非分区 + `event_time DESC` 索引（契约给的"等价分批归档"出口），演进路径见 5.5 |
| 6 | 原始响应可独立归档，重放窗口内可达 | 原始载荷双侧留存：source.raw（列表条目）+ data_detail.raw（详情/PDF），重放 = 按行内 adapter/parser 快照重解析；不设独立归档表 |

## 五、关键设计决策

### 5.1 状态分两类：数据事实与执行态

- **数据事实**（源站侧的客观状态）：`dead`（源站删文）、`paywalled`（付费墙）、`filtered`（广告/站外跳转）——留在 `data_source.status` 与 `data_detail.status`；
- **执行态**（采集侧的、可重建的）：详情抓没抓到是推导态（表 4 有无此行）；失败计数/重试时间等记录在 extra 扩展字段（约定键，可重建清理）。

### 5.2 回填：进度是推导态

```sql
-- 找"还没抓到详情的正常条目"（回填任务的取件查询）
SELECT i.*
FROM data_source i
LEFT JOIN data_detail c USING (channel_id, record_key)
WHERE i.channel_id = $1
  AND i.status = $2                              -- 代码枚举 ItemStatus.Normal 的数值
  AND c.id IS NULL
  AND i.event_time > now() - interval '3 days'   -- 只扫增量尾巴
ORDER BY i.event_time DESC;
```

### 5.3 列表即全文不搞特例

「列表即全文」的源（快讯五源、格隆汇 live）data_source/data_detail 两表都写：详情段由列表适配器直接产出（detail_adapter 与自身同源），`fetch_url` 填条目自身。收益："详情去哪找"对所有渠道是同一个答案，分析层与回填逻辑不按渠道分叉。

### 5.4 写入语义：唯一覆盖式 upsert（适配器声明）

重复数据的统一做法是**覆盖**：ON CONFLICT DO UPDATE，只有这一种写入语义，由适配器声明（适配器知道自己抓的数据会不会被源站修订），channel 行不设 write_mode 列。覆盖发生在两层：

- **data_source**：按 `(channel_id, record_key)`（资源唯一性），哈希条件防元数据修订空转；
- **data_detail**：按 `(source_id, record_key)`（内容唯一性），哈希条件防内容空转。

"要最新态"还是"要历史"由 **detail 内容键的预映射选型**表达（record_key 恒为「渠道前缀id:sha256」）：

- 要最新态：预映射 = 源内稳定 id（文章 id / 电报 id / slug）→ 同键哈希覆盖；
- 要历史快照：预映射 = 条目标识 + 时间窗（榜单按天）→ 同资源每窗新行，历史天然保留。

```sql
-- 唯一写入形态（Storage 层手拼，以 data_source 为例）
... ON CONFLICT (channel_id, record_key) DO UPDATE SET
        title = EXCLUDED.title,
        extra = EXCLUDED.extra,
        content_hash = EXCLUDED.content_hash,
        update_time = now()
    WHERE data_source.content_hash IS DISTINCT FROM EXCLUDED.content_hash;
-- WHERE 哈希条件是实现优化而非模式：内容未变不推进 update_time，避免同步水位空转；
-- IS DISTINCT FROM 兼容首插 content_hash IS NULL 的边界；
-- data_detail 侧同型：ON CONFLICT (source_id, record_key)，content_hash 为 raw 的哈希
```

### 5.5 暂不原生分区

当前量级（财经文本日增数万行）非分区 + `event_time DESC` 索引足够；且 PG 分区表的唯一约束必须包含分区键，原生分区会迫使 `(channel_id, record_key)` 去重键变形为 `(event_time, channel_id, record_key)`，并引入"源站修订 event_time 导致同 record_key 跨分区"的语义负担。量级到千万行再转 RANGE 分区，`retention_days` 已是保留期治理的挂载位。

### 5.6 update_time 不建触发器

写入全部收敛到 Storage 层统一出口，SQL 显式 `SET update_time = now()`，不留旁路。

### 5.7 channel 的克制边界

channel 只承载"分类归属 + 适配器配置 + 实例参数 + 节奏监控"：

- `monitor` 声明新鲜度告警阈值（快讯类分钟级 / 政策类天级），健康探测"注册即覆盖"的依据；
- `last_success_at` 是运维缓存（可从数据重算），换取控制台渠道全景一次查询；
- `description` 承载站点侦察结论与已知坑，就近可查。

考虑过但不加（克制）：

- `host` / `site` 列：归属层级已由分类表承载；真实 host 运行时从适配器的 URL 模板解析并缓存即可，列上冗余会漂移；
- `dataset` 分组列：跨渠道逻辑组合（"快讯" = 五个渠道）是分析层 AnalysisView 注册的职责，不在渠道行上冗余归属；
- `item_count` 类统计缓存：可推导，要缓存走物化引擎，不在配置表上攒；
- 调度优先级：单机形态没有抢占需求；
- 代理偏好：请求配置已固化进适配器实现；代理池真正落地时再评估独立的配置位。

约束强化：`retention_days` 加正数约束；枚举列已统一为 dict 数字外键（5.8），全表不再有 CHECK 型枚举列（dict.type / dict.status 自举例外除外）。

### 5.8 枚举统一机制：dict 数字外键

所有枚举列统一为 dict 数字外键（int REFERENCES dict(id)，列名不带 `_id` 后缀），一种机制、没有例外分支。不用 PG 原生 ENUM：加值要 ALTER TYPE 且不能删值，类型爆炸，任何演化都是重量级迁移。

配套规则：

1. **列名不带 `_id` 后缀**：枚举列直接叫 `status` / `adapter` / `parser`（int + dict 外键）；实体引用列（`channel_id` / `category_id`）保留 `_id` 后缀——后缀区分"枚举取值"还是"引用实体"；
2. **id 钉死，代码枚举为准**：dict 种子行显式指定 id（migration 落地），数值与代码枚举一一对应；代码只写枚举、不写魔法数字，数据库只记录数字。id 不能由自增产生（各环境序列值不同，无法与代码枚举对齐）；种子后 `setval` 校正序列，日常新增取值显式取下一 id。枚举列与 dict.id 用 **int**：dict 行数人工封顶（没有"增长到 21 亿"的可能），且 int 与 C# 枚举默认底层类型一致、写入免转换；数据表的标识列（id/channel_id 等）仍是 **bigint**——自动生成的标识没有结构上限，不赌范围；
3. **新增枚举三同步**：migration 插入新 id 行 + 代码枚举加值 + 相关列 COMMENT 同步取值映射——三处缺一不可（COMMENT 是数据库侧唯一的取值映射文档）；
4. **自举例外**：`dict.type` / `dict.status` 是枚举机制自身的载体，保留 text + CHECK，不引用自身——全库仅有的两处非 dict 枚举列。

### 5.9 重跑与重试：指令驱动 + extra 执行态

- **手动重跑**：控制台指令通道（架构 4.9 任务控制）触发——重跑失败项、重拉历史窗口，参数随指令走，任务完成即消；
- **失败重试**：失败计数/下次重试/最近错误等执行态记录在 data_source/data_detail 的 extra 扩展字段（约定键 `fail_count` / `next_retry_at` / `last_error`，已确认；新增约定键须先与项目所有者确认），行可重建、执行态可清零，不设独立状态表；
- **解析重放**：原始载荷双侧留存——source.raw（列表条目）重放修正投影列，data_detail.raw（详情/PDF）重放产出内容解析；均按行内 adapter/parser 快照执行（契约第 6 条）。

## 六、渠道形态覆盖验证（v1 七条管线装填）

| v1 管线 | 资源（data_source） | 内容（data_detail） | 写入语义（统一覆盖） | 说明 |
|---|---|---|---|---|
| 网页新闻（东财/财联/新浪/见闻/金十/同花/格隆/每经） | 每篇文章一资源 | ✓ 正文（1:1，key=常量） | 覆盖（修订生效） | 列表发现资源 → 详情回填 |
| 实时快讯（五源） | 列表接口一资源 | ✓ 每条一内容（1:N，key=电报id） | 覆盖 | 同源直出 |
| 研报（东财三类） | 每篇一资源 | ✓（1:1） | 覆盖（摘要回填 extra） | 列表即元数据 |
| 盘面榜单（龙虎榜/大宗/两融） | 每榜单接口一资源（链接恒定） | ✓ 每交易日一份（key 含日期） | detail 哈希修订 | 时间进内容键，历史天然保留 |
| 公告（巨潮） | 每公告一资源 | ✓ PDF 原样进 raw（key=pdf） | 覆盖 | 元数据先行，PDF 可按节奏回补 |
| 官方文件（统计局/证监会） | 每文件一资源 | ✓ 正文页 HTML（1:1） | 覆盖（正文修订生效） | 文号/附件进 extra |
| 数据集（loot-drop） | 对账资源一行 | ✓ 每案例一行（key=slug） | detail 哈希修订 | 有界集合，行会修订 |

结论：七种形态在"资源 : 内容"模型下全部同构装填（1:N 或 1:1）；结构化解析产物统一归分析侧，不进采集表。
