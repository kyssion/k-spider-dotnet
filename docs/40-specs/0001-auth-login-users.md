# 0001. 登录与账号管理

> 状态：草案
> 最后更新：2026-11-09
> 关联 ADR：无（行为与接口契约见 [auth.md](../10-architecture/auth.md)）

## 目标

让运维人员能够登录控制台、修改自己的密码，并在同一页面管理其他账号的展示名、启停与密码重置。

## 非目标

- 不做角色、权限或菜单级授权；当前所有登录用户同权；
- 不做多因素认证、SSO、扫码登录或第三方身份源；
- 不做账号自助注册、邮件找回或运维 CLI 恢复工具；
- 不做前端多语言；文案以当前界面语言为准；
- 不改变 [auth.md](../10-architecture/auth.md) 已定义的接口、Cookie 与 CSRF 语义。

## 用户场景

- 作为运维人员，我希望用初始化账号登录控制台，以便开始配置渠道与查看数据；
- 作为已登录用户，我希望修改自己的密码，以便在默认密码泄露风险下主动轮换；
- 作为已登录用户，我希望创建、停用、启用账号并重置他人密码，以便交接和回收访问权限。

## 契约

| 项 | 内容 |
| --- | --- |
| 涉及聚合 | `sys_user` |
| 新增/修改端点 | 按 [auth.md](../10-architecture/auth.md)「数据与接口」；本规格不新增端点 |
| 新增错误码 | 无新增；失败语义按 [auth.md](../10-architecture/auth.md)「登录」与「未登录行为」 |
| 前端路由 | `/login`、`/settings/users` |

## 验收标准

- [ ] 空库初始化后存在 `admin` 账号，使用默认密码可以登录成功；部署文档要求首次登录后修改密码。
- [ ] 用户名不存在、密码错误、账号被禁用三种情况统一返回 `401`，响应文案不区分具体原因。
- [ ] 勾选“7 天免登录”时 Cookie 带 `ExpiresUtc = 登录时间 + 7d`；不勾选时写入浏览器会话 Cookie。
- [ ] 会话 Cookie 具备 HttpOnly、SameSite=Strict、Path=/、host-only；生产 HTTPS 下 Secure 开启，Development 本地 HTTP 可按配置关闭。
- [ ] 已禁用账号在下一次请求即被拒绝，服务端清除 Cookie；不依赖前端主动登出。
- [ ] 未登录访问受保护页面返回 `302 /login?returnUrl=...`；访问业务 API 返回 `401 application/json`；访问 `/api/health`、`/api/auth/login`、`/login` 与静态资源保持匿名可访问。
- [ ] 登录接口校验 `Origin` / `Referer` 与当前站点同源；非同源请求失败且不签发 Cookie。
- [ ] 除登录外的 `POST` / `PUT` / `PATCH` / `DELETE` 请求缺少或携带错误 `X-CSRF-TOKEN` 时返回拒绝，且不产生写操作。
- [ ] 修改密码需要当前密码；新密码长度 8–128，允许空格与 Unicode；当前密码错误时不更新摘要。
- [ ] 密码摘要命中 `SuccessRehashNeeded` 时，登录成功后用当前参数重新哈希并持久化。
- [ ] 账号列表字段按 [auth.md](../10-architecture/auth.md)「账号管理」；新建账号的用户名满足 `sys_user` 的 CHECK 约束。
- [ ] `PATCH /api/users/{id}` 至少包含 `displayName` 或 `status` 之一；同时包含时一并更新；两者都缺失时返回参数错误。
- [ ] 禁用自己或禁用最后一个 `active` 账号被拒绝，且账号状态保持不变。
- [ ] 重置密码作用于其他账号；修改自己的密码必须走修改密码接口。
- [ ] 账号的创建、展示名修改、启停、重置密码都写应用日志，至少包含操作者、目标账号、动作与时间。
- [ ] 数据库、网络或密码哈希异常不泄漏堆栈与内部消息；对外返回统一的服务器错误。

## 边界与异常

- 空数据：`sys_user` 为空时初始化默认账号；账号列表为空时页面显示空态而不是错误。
- 超长输入：用户名、展示名与密码超长时按 DDL 与 [auth.md](../10-architecture/auth.md)「密码」拒绝，不截断。
- 并发/重复提交：同一账号被并发禁用时，以数据库最终状态为准；最后一个 active 账号的判定必须在同一事务边界内完成。
- 网络失败：前端展示统一错误并保留当前登录态；写请求失败不得乐观更新列表或状态。
- Cookie 被篡改或密钥轮换：服务端拒绝该票据并清除 Cookie，用户回到登录页。
- CSRF token 过期：前端重新获取 `/api/auth/me` 后重试；不得静默关闭校验。
